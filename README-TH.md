# Daily Report v1.0 — แอป Android (APK) + โปรแกรม Windows (.exe) + ล็อกอินซิงค์ข้อมูลข้ามเครื่อง

โฟลเดอร์นี้ห่อไฟล์ `daily-report.html` ด้วย Capacitor แล้วให้ GitHub สร้างไฟล์ `.apk` ให้อัตโนมัติ
คุณไม่ต้องติดตั้ง Android Studio — แค่สร้าง repo, อัปโหลดไฟล์, กดรัน


## ขั้นที่ 0 (ทำครั้งเดียว): ตั้งเซิร์ฟเวอร์ซิงค์ Firebase — ฟรี ประมาณ 10 นาที

ระบบล็อกอินใช้ **Firebase Authentication (อีเมล/รหัสผ่าน)** และเก็บข้อมูลที่ **Cloud Firestore** ของ Google
ทุกเครื่อง (มือถือ APK และคอมพิวเตอร์) ที่เข้าสู่ระบบด้วยอีเมลเดียวกันจะเห็นข้อมูลชุดเดียวกัน แต่ละบัญชีเห็นเฉพาะข้อมูลของตัวเอง

1. เข้า **console.firebase.google.com** → **Create a project** (ตั้งชื่อ เช่น `daily-report-bl`) → ปิด Google Analytics ได้
2. เมนู **Build → Authentication** → **Get started** → แท็บ **Sign-in method** → เปิด **Email/Password** → Save
3. เมนู **Build → Firestore Database** → **Create database** → เลือก location **asia-southeast1 (Singapore)** → **Start in production mode**
4. ใน Firestore แท็บ **Rules** → ลบของเดิม แล้ววางเนื้อหาจากไฟล์ `firestore.rules` ในชุดนี้ → **Publish**
5. ไอคอนเฟือง **Project settings** → **Your apps** → กดไอคอน `</>` (Web) → ตั้งชื่อ → **Register app**
   จะเห็น `firebaseConfig` ให้จดค่า **apiKey** (ขึ้นต้นด้วย `AIza...`) และ **projectId**
6. ใส่ค่าให้แอป เลือกวิธีใดวิธีหนึ่ง:
   - **แนะนำ:** ใน repo GitHub ไปที่ **Settings → Secrets and variables → Actions → แท็บ Variables → New repository variable**
     สร้าง `FIREBASE_API_KEY` และ `FIREBASE_PROJECT_ID`
   - หรือแก้ไฟล์ `firebase-config.json` ใน repo ใส่ทั้งสองค่า

ค่า apiKey ของ Firebase ไม่ใช่รหัสลับ (ฝังในแอปได้ตามปกติ) ความปลอดภัยของข้อมูลมาจาก Rules ในข้อ 4
โควตาฟรี (Spark plan): อ่าน 50,000 / เขียน 20,000 ครั้งต่อวัน และพื้นที่ 1 GB — เพียงพอสำหรับทีมผู้ควบคุมงาน

## ขั้นตอนสร้าง APK

1. เข้าสู่ระบบ **github.com** → กด **New repository** → ตั้งชื่อ เช่น `daily-report-android` → เลือก **Private** (แนะนำ) → **Create repository**
2. กด **uploading an existing file** แล้ว **ลากไฟล์และโฟลเดอร์ทั้งหมดในโฟลเดอร์นี้** ไปวาง
   (ต้องมี `.github`, `scripts`, `src`, `fonts-src`, `resources`, `desktop` และไฟล์ `package.json`, `capacitor.config.json`, `firebase-config.json`, `firestore.rules`)
   - ถ้าเบราว์เซอร์ไม่ยอมอัปโหลดโฟลเดอร์ที่ขึ้นต้นด้วยจุด (`.github`): กด **Add file → Create new file** พิมพ์ชื่อ `.github/workflows/build-apk.yml` แล้วคัดลอกเนื้อหาจากไฟล์ในชุดนี้ไปวาง
   - กด **Commit changes**
3. ไปที่แท็บ **Actions** → ถ้ามีปุ่มให้เปิดใช้งาน ให้กดอนุญาต → เลือก **Build Android APK + Windows EXE** → **Run workflow**
   (หรือรอให้รันเองหลังอัปโหลดก็ได้) ใช้เวลาประมาณ 6–12 นาที
4. เมื่อเป็นเครื่องหมายถูกสีเขียว → คลิกรอบที่รัน → เลื่อนลงล่างสุดที่ **Artifacts** → ดาวน์โหลด **DailyReport-v1.0-debug-apk** (ไฟล์ .zip ข้างในมี `DailyReport-v1.0-debug.apk`)
   และ **DailyReport-v1.0-web-for-computer** = ไฟล์ `daily-report.html` สำหรับเปิดบนคอมพิวเตอร์ (ฝังค่าเซิร์ฟเวอร์แล้ว)
5. ส่งไฟล์ `.apk` เข้ามือถือ (LINE, Drive, สาย USB) → เปิดไฟล์ → อนุญาต **ติดตั้งจากแหล่งที่ไม่รู้จัก** เมื่อระบบถาม → ติดตั้ง


## โปรแกรมสำหรับคอมพิวเตอร์ Windows (.exe)

workflow เดียวกันสร้างไฟล์ Windows ให้ด้วย (งาน `windows` ใช้เวลาประมาณ 5–10 นาที) ดาวน์โหลด artifact **DailyReport-v1.0-windows-exe** ข้างในมี 2 ไฟล์:

- `DailyReport-Setup-1.0.exe` — **ตัวติดตั้ง (แนะนำ)** ดับเบิลคลิกครั้งเดียว ติดตั้งให้ผู้ใช้คนนั้นโดยไม่ต้องใช้สิทธิ์ผู้ดูแลเครื่อง สร้างไอคอน **Daily Report** บน Desktop และ Start menu
- `DailyReport-1.0-portable.exe` — แบบพกพา ไม่ต้องติดตั้ง ดับเบิลคลิกใช้ได้เลย (เหมาะกับเครื่องที่ห้ามติดตั้งโปรแกรม)

ทั้งสองแบบใช้ข้อมูลชุดเดียวกัน เก็บอยู่ที่ `%APPDATA%\Daily Report` (ถอนการติดตั้งแล้วข้อมูลยังอยู่) และเข้าสู่ระบบ/ซิงค์กับมือถือได้ด้วยอีเมลเดียวกัน

- ครั้งแรก Windows อาจขึ้น **“Windows protected your PC”** เพราะไฟล์ไม่ได้ลงนามดิจิทัล → กด **More info → Run anyway** (ถ้าต้องการเลิกขึ้นคำเตือนต้องซื้อใบรับรอง Code Signing)
- ใช้ได้กับ Windows 10 / 11 แบบ 64 บิต ใช้งานออฟไลน์ได้ (ยกเว้นการซิงค์และ OCR)
- บันทึก PDF / ไฟล์สำรอง .json จะเปิดหน้าต่าง Save ของ Windows (เริ่มที่โฟลเดอร์ Documents)
- เมนู **มุมมอง** ใช้ขยาย/ย่อตัวอักษร (Ctrl + / Ctrl -) และเต็มจอ (F11)
- อัปเดตเวอร์ชัน: ติดตั้งไฟล์ Setup ตัวใหม่ทับได้เลย ข้อมูลไม่หาย



## ประกาศเขตภัยพิบัติ (ใส่ “ปัญหาและอุปสรรค” อัตโนมัติ)

- ข้อมูลโครงการมีช่อง **หมู่ที่ / ตำบล / อำเภอ / จังหวัด** (พิมพ์สถานที่ก่อสร้าง เช่น “ม.4 ต.ท่างิ้ว อ.เมืองนครศรีธรรมราช จ.นครศรีธรรมราช” แอปเติมให้เอง)
- เมนู **ประกาศภัยพิบัติ** (หน้าแรก / เมนูด้านข้าง / ปุ่มในหัวข้อปัญหาและอุปสรรค) → **เพิ่มประกาศ**: ประเภทภัย เลขที่ประกาศ ลงวันที่ วันที่มีผล–สิ้นสุด (ว่าง = จนกว่าจะยกเลิก) และพื้นที่ อำเภอ/ตำบล/หมู่ (หมู่ว่าง = ทั้งตำบล, ใส่ได้แบบ 1,3,5-8)
- ก่อนบันทึก แอปแสดงว่ามีโครงการไหน กี่รายงาน ที่อยู่ในพื้นที่และช่วงวันที่
- รายงานทุกฉบับที่ตรงพื้นที่และวันที่ จะมีข้อความ “- อยู่ในช่วงประกาศเขตการให้ความช่วยเหลือผู้ประสบภัยพิบัติกรณีฉุกเฉิน (…) ตามประกาศจังหวัด… ที่ … ลงวันที่ … (มีผล …)” บรรทัดแรกของช่องปัญหาและอุปสรรค
- แก้วันที่/พื้นที่ของประกาศ → ข้อความในรายงานอัปเดตตาม · ลบประกาศ → ข้อความที่แอปใส่ถูกลบ (ข้อความที่พิมพ์เองไม่หาย)
- ลบหรือแก้ข้อความนั้นในรายงานใดเอง แอปจะไม่ใส่ซ้ำในรายงานนั้น (กด “ใส่ข้อความอีกครั้ง” ได้)
- ประกาศซิงค์ไปทุกเครื่องที่เข้าสู่ระบบบัญชีเดียวกัน

## สภาพอากาศส่วนกลาง (ใช้ร่วมกันในตำบลเดียวกัน)

- ในหัวข้อ **โครงการ** มีช่อง **ตำบล** (ถ้าสถานที่ก่อสร้างมี “ต.xxx” แอปจะเติมให้เอง)
- โครงการที่ใส่ตำบลเดียวกัน → บันทึกสภาพอากาศของวันนั้นครั้งเดียว รายงานของทุกโครงการในตำบลนั้นได้ข้อมูลเดียวกันอัตโนมัติ (แก้จากโครงการไหนก็เปลี่ยนตามกันหมด) และซิงค์ข้ามเครื่องด้วย
- ถ้าหน้างานไหนสภาพอากาศต่างจากที่อื่น กด **แยกเฉพาะโครงการนี้** · กลับมาใช้ร่วมกันได้ด้วยปุ่ม **ใช้ส่วนกลาง**
- รายงานเก่าที่บันทึกไว้แล้วและต่างจากส่วนกลาง จะถูกเก็บแยกไว้ตามเดิม ไม่ถูกทับ

## การเข้าสู่ระบบและซิงค์

- เปิดแอปครั้งแรกจะขึ้นหน้า **บัญชีและการซิงค์** → กด **สมัครบัญชีใหม่** (ครั้งแรก) หรือ **เข้าสู่ระบบ**
  เปิดภายหลังได้ที่ปุ่มรูปเมฆบนหน้าแรก, เมนู **ตั้งค่า → บัญชีและการซิงค์** หรือเมนูด้านข้าง **บัญชี / ซิงค์** (Desktop UI)
- บนคอมพิวเตอร์: ใช้โปรแกรม `.exe` (แนะนำ) หรือเปิด `daily-report.html` (จาก artifact web-for-computer) ด้วย Chrome แล้วเข้าสู่ระบบด้วยอีเมลเดียวกัน
  ถ้าใช้ไฟล์ HTML ที่ยังไม่ได้ฝังค่า ให้เปิด **ตั้งค่าเซิร์ฟเวอร์ (สำหรับผู้ดูแลระบบ)** แล้ววาง firebaseConfig ครั้งเดียว
- ทำงานแบบออฟไลน์ได้: บันทึกลงเครื่องก่อน แล้วซิงค์เองเมื่อมีอินเทอร์เน็ต (ทุกครั้งที่แก้ไข ~4 วินาที และทุก 1 นาทีขณะเปิดแอป)
- ถ้าแก้รายงานฉบับเดียวกันจาก 2 เครื่องพร้อมกัน ฉบับที่แก้ **ล่าสุด** จะถูกใช้
- เครื่องใหม่ที่ยังว่าง: เข้าสู่ระบบแล้วดึงข้อมูลทั้งหมดลงมา · เครื่องที่มีข้อมูลอยู่แล้ว: รวมเข้ากับบัญชี
- เครื่องใช้ร่วมกัน: เลือก **ออกจากระบบและล้างข้อมูลในเครื่องนี้** (ข้อมูลบนเซิร์ฟเวอร์ไม่หาย)
- โหมดหน้าจอ Mobile/Desktop ไม่ซิงค์ (แต่ละเครื่องเลือกเอง) ส่วนการตั้งค่าอื่น ชื่อหน่วยงาน โลโก้ โครงการ รายงาน ภาพ และลายเซ็นซิงค์ทั้งหมด
- ลืมรหัสผ่าน: ใส่อีเมลแล้วกด **ลืมรหัสผ่าน** ระบบส่งลิงก์ตั้งรหัสใหม่ทางอีเมล

## การใช้งานในแอป

- **บันทึก PDF / สำรองข้อมูล .json**: แอปจะเปิดหน้าต่าง "แชร์" ของ Android → เลือกบันทึกลง Drive / ไฟล์ / LINE / อีเมลตามต้องการ
- ข้อมูลเก็บในเครื่อง (IndexedDB ของแอป) และบนเซิร์ฟเวอร์เมื่อเข้าสู่ระบบ — ถ้า **ไม่ได้** เข้าสู่ระบบ การถอนแอปจะทำให้ข้อมูลหาย ควรสำรอง .json เป็นระยะ
- ฟอนต์ IBM Plex Sans Thai / Sarabun และไลบรารีสร้าง PDF รวมอยู่ในแอป ใช้งานออฟไลน์ได้
- ฟีเจอร์ที่ **ต้องใช้อินเทอร์เน็ต**: การซิงค์/เข้าสู่ระบบ และอ่านภาพ/สแกน ปร.4 ด้วย OCR (โหลดข้อมูลภาษาไทยครั้งแรก)
- ปุ่มย้อนกลับของ Android: ปิดหน้าต่างที่เปิดอยู่ → กลับหน้าแรก → ออกจากแอป

## ความปลอดภัย (สรุป)

- ไม่โหลดสคริปต์จากอินเทอร์เน็ตเข้าแอป (ไลบรารีอยู่ในตัวแอป) และมี Content-Security-Policy
- ปิดการสำรองข้อมูลอัตโนมัติของ Android (`allowBackup=false`), ปิด cleartext (http), ปิดการดีบัก WebView
- ไฟล์สำรอง .json ที่นำเข้าจะถูกตรวจ/ล้างก่อนใช้ (ภาพต้องเป็น data:image, ตัดคีย์อันตราย) และข้อความทุกช่องถูก escape
- ข้อมูลในเครื่องไม่ได้เข้ารหัส — ใครปลดล็อกมือถือได้ก็เปิดแอปได้ ควรตั้งล็อกหน้าจอ
- ไฟล์ **debug APK** ใช้ติดตั้งภายในหน่วยงานได้ แต่ไม่เหมาะกับการเผยแพร่สาธารณะ

## (ไม่บังคับ) APK แบบลงนาม สำหรับแจกจ่าย / Google Play

1. สร้าง keystore บนคอมพิวเตอร์ (ต้องมี Java):
   `keytool -genkey -v -keystore release.keystore -alias dailyreport -keyalg RSA -keysize 2048 -validity 10000`
2. แปลงเป็น base64: Linux/Mac `base64 -w0 release.keystore` / Windows PowerShell `[Convert]::ToBase64String([IO.File]::ReadAllBytes("release.keystore"))`
3. ใน GitHub: **Settings → Secrets and variables → Actions → New repository secret** สร้าง 4 ตัว:
   `KEYSTORE_B64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` (เช่น dailyreport), `KEY_PASSWORD`
4. รัน workflow อีกครั้ง จะได้ Artifact **DailyReport-release-apk** เพิ่ม
5. **เก็บไฟล์ keystore และรหัสผ่านไว้ให้ดี** — หายแล้วอัปเดตแอปเดิมไม่ได้
6. ถ้าจะขึ้น Google Play ต้องใช้ไฟล์ .aab และค่าสมัครนักพัฒนา (ครั้งเดียว ~25 USD) — ต้องปรับ workflow เพิ่ม
